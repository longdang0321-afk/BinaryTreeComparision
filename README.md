# BinaryTreeComparision
comparison between sequential search anhd BST search
과제 05: 순차 탐색과 BST 탐색의 비교

비교 횟수 기준: 순차 탐색은 원소 하나와 비교할 때마다 1회, BST는 노드 하나를 방문할 때마다 1회로 센다 (삽입·탐색 동일). 빈 트리에 첫 노드를 넣을 때는 비교가 없다.

1. 실행 결과
탐색 대상 50개 중 찾은 것은 3개, 못 찾은 것은 47개이다.
항목	순차 탐색	BST 탐색
총 비교 횟수	4,833	376
평균 비교 횟수	96.66	7.52
BST 생성 비교 횟수	-	641
총 비용 (생성 + 탐색)	4,833	1,017

2. 두 탐색 방법의 성능 차이
BST 탐색이 순차 탐색보다 약 12.9배 적게 비교했다.
순차 탐색: 배열이 정렬되어 있지 않아 한 번 비교해도 원소 하나만 제외할 수 있다. 최악의 경우 n번 비교하며 O(n)이다.
BST 탐색: 노드에서 한 번 비교할 때마다 한쪽 서브트리 전체를 제외하므로 비교 횟수가 트리 높이에 비례한다.
탐색 대상 중 47개가 BST에 없는 값이었다. 1001개 값 중 100개만 저장되어 있어 key가 존재할 확률이 약 10%이기 때문이다. 순차 탐색은 실패하면 항상 100회를 모두 비교하므로 평균이 100에 가까운 96.66이 되었다 (찾은 3개의 평균은 44.33). BST는 실패해도 평균 7.43회였다 (찾은 3개의 평균은 9.00).


3. BST 생성 비용을 고려한 분석
BST를 만드는 데 641회가 들었다 (노드당 평균 6.41회). 삽입할 때마다 루트에서 삽입 위치까지 내려가며 비교하기 때문이다.
생성 비용을 포함해도 BST는 1,017회로, 순차 탐색 4,833회보다 약 3,816회 (약 4.75배) 적다.
탐색 1회당 평균 96.66 − 7.52 ≈ 89.1회를 절약하므로 손익분기점은 641 / 89.1 ≈ 7.2회이다. 탐색을 7번 이하로 한다면 BST를 만드는 비용이 더 크고, 50번 탐색하는 이번 실험에서는 BST가 유리하다.


4. 트리 구조에 따른 탐색 성능 변화
실험 결과: 생성된 BST의 높이는 13이었다. 노드 100개로 만들 수 있는 가장 균형 잡힌 트리의 높이는 7이므로, 입력 순서 때문에 트리가 한쪽으로 치우친 부분이 있다는 뜻이다. 실제로 BST 탐색의 비교 횟수는 key마다 3회에서 12회까지 달랐다. 그래도 평균 7.52회로 순차 탐색보다 훨씬 적었다.
이론적 분석 (직접 측정하지 않음): 값이 정렬된 순서로 삽입되면 모든 노드가 한쪽 자식으로만 이어져 연결 리스트가 된다. 이때 생성 비교 횟수는 1+2+…+99 = 4,950회이고, 탐색은 최대 100회로 순차 탐색과 같아진다. 위 실험 기준으로 생성 비용만 7배 이상이 되어 BST를 쓰는 이점이 사라진다.
결론: BST가 빠른 이유는 구조 자체가 아니라 트리 높이가 낮기 때문이다. 이번 실험은 값이 랜덤 순서였기 때문에 높이가 낮게 유지되었고, 높이가 커지면 성능은 순차 탐색에 가까워진다.
